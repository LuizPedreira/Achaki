Achados & Perdidos - Fatec (versão fiel v5)

Versão estática para GitHub Pages, construída em HTML, CSS e JavaScript com localStorage.

#Contas de demonstração

**Usuário**
- E-mail: `ana.rocha@fatec.sp.gov.br`
- Senha: `1234`

**Administrador**
- E-mail: `admin@fatec.sp.gov.br`
- Senha: `admin123`

#Registros padrão
- Fone de ouvido — cadastrado por Ana.
- Carteira — cadastrada por Lucas.
- Chave de carro — cadastrada por Maria.

Portanto, ao entrar como Ana, apenas o fone aparece como registro encontrado dela. Os outros itens são públicos, mas pertencem a outros usuários.

#Fluxo público
A aplicação abre diretamente na listagem de itens, sem exigir login. Ao abrir um item, a área de contato fica bloqueada e ofuscada. O botão de login retorna o usuário ao mesmo item após autenticar, liberando o botão do WhatsApp.

#GitHub Pages
Envie todos os arquivos desta pasta para a raiz do repositório e use Settings > Pages > Deploy from a branch > main > /(root).

#Observação
Como é GitHub Pages, os dados cadastrados permanecem no localStorage do navegador e não sincronizam entre dispositivos.


#Melhorias da versão 6
- Área de contato bloqueado redesenhada, sem textos sobrepostos.
- O usuário pode informar no cadastro se o item já foi devolvido.
- Quando o item permanece com quem encontrou, o próprio usuário pode registrar a devolução depois em Meus registros.
- Quando o item está na Fatec, a interface informa que a devolução é responsabilidade do administrador.
- Registro de devolução guarda proprietário, data, telefone e observações.
- Administrador pode vincular uma devolução a uma solicitação de item perdido.
- Administrador pode registrar a recuperação diretamente na tela de itens perdidos.
- O usuário que perdeu passa a ver o item como recuperado e pode avaliar a devolução quando houver vínculo.
- Histórico administrativo informa a forma de devolução.


#Auditoria de requisitos — versão v7

##Requisitos funcionais
- **RF01** Cadastro de usuário: nome, e-mail, senha e telefone.
- **RF02** Login/autenticação com perfis Usuário e Administrador.
- **RF03** Item encontrado com foto, descrição, categoria, local, data, situação de devolução e posse atual (usuário/Fatec).
- **RF04** Registro de item perdido com descrição, categoria e data aproximada.
- **RF05** Busca/filtros por categoria, palavra-chave, período, local e status.
- **RF06** Exibição pública dos itens encontrados aprovados.
- **RF07** Administrador altera status: Em aberto, Reservado e Devolvido.
- **RF08** Histórico separado de devolvidos e não devolvidos.
- **RF09** Administrador edita/exclui registros; duplicidade idêntica é bloqueada no cadastro.
- **RF10** Avaliação/feedback após devolução.
- **RF11** Cadastro informa se o item está com o usuário ou na Fatec.
- **RF12** Administrador registra a devolução com proprietário, data, contato/documento e observações; devolução direta também pode ser registrada pelo usuário quando o item está com ele.

##Não funcionais aplicáveis ao protótipo
- Interface responsiva mobile/desktop.
- Senhas não são armazenadas em texto puro; o protótipo usa hash SHA-256 no navegador.
- Código estático HTML/CSS/JS, adequado a GitHub Pages.
- Validação de duplicidade de registros idênticos.
- Código versionável no Git/GitHub.

**Observação:** disponibilidade de 95% depende do serviço de hospedagem escolhido e não pode ser garantida apenas pelo código estático. Os requisitos desejáveis RD01–RD04 continuam classificados como desejáveis no documento e não são apresentados como integrações reais quando não existe o serviço externo correspondente.
